# DV02: scény, provedení a diagnostika

Autoritativní zadání je [specifikace revize 2.0](dv02-spec.md). Tento dokument
popisuje implementaci a její důkazní hranice; [coverage](dv02-coverage.json)
mapuje jednotlivé požadavky a scénářové rodiny. [privátní evidence](development-coordination.md)
odděluje software A–F od externí akceptace G. H se neimplementuje.
[Výkonový přehled](dv02-performance-v4.json) rozlišuje host měření, linked ESP
sekce a dosud neznámé hodnoty za běhu na sestavě.

## Zdroj a vlastníci

Výchozí checkout byl čistý `74f215fc371e19780a3521adf0f7b79dcdb068a5`.
`mechanika/final/effects.json` je jediný autorský zdroj barev a časů. Jeho běžná
a krátká sekvence už před DV02 obsahovaly přípravu a úplný raise/show/lower/rest
lifecycle. Překladač zachovává legacy RGB i fyzický scaling; ilustrační časy jízdy
ve vieweru nejsou kalibrací. Nezávislý legacy fixture vzniká z původního zdroje,
nikoli zpětným výpočtem z nového compileru.

Navíc `compare_legacy_show.py` kompiluje skutečné původní i současné core se
stejným záznamovým portem: main/short × šest slotů, kalibrace 500 ms a tick 10 ms.
Shodují se celé LED rámce, audio requests, povely a intervaly vibrací/serv,
časové značky i journal outcome. Main trvá 9790 ms, short 6970 ms. Zůstávají
i původní dva 10ms handoff intervaly. Je to hostitelský důkaz, nikoli měření kufru.

| Oblast | Existující autorita a cesta | Konflikty / důkazní omezení |
|---|---|---|
| Výběr | Backend validovaný výsledek → PendingProposal → WandPresentation | Scéna nerozhoduje o hůlce, slotu ani katalogu. |
| Fyzická show | WandPresentation → PhysicalPresentation → PhysicalEffects | Jediný řídicí task; žádná fronta show ani druhý přehrávač. |
| Safety a pohyb | SafetyController, DeviceControlRuntime, PhysicalEffects, provisionovaná kalibrace | Servo a vibrace se nesouběží; Stop/fault nespouští návrat. |
| Ruční ovládání | LocalControlOwner / SelectionSequence | Výlučný lease; ztráta lease ukončí ruční operaci. |
| Dance | DanceCoordinator / EspIdfDancePlayer / SD owner | Vlastní stream, životní cyklus a audio; presentation ani accent ho nepřebírají. |
| Řeč a tón | EspIdfVoiceAudio | Aktivní řeč odmítá volitelný tón. StopCues neruší řeč ani Dance. |
| Kritická evidence | PersistentCommandJournal před prvním efektem | Debug trace není idempotence evidence; nejasná operace po bootu vyžaduje inspekci. |
| Pozorování | Pevný ring → ShowTraceMailbox → existující místní HTTPS | Kopie bez čekání v ticku; export a serializace jsou práce HTTP tasku. |
| Viewer | effects.plan.json + import stop stejného C++ core | Čistě read-only; CAD animace zůstává označená jako ilustrace. |

Původní příprava po každém pozdním ticku posouvala začátek další fáze. DV02
počítá pevné due times a vynechá prošlé dekorace, místo aby přehrával zpožděné
pulzy. Celkový deadline se neobnovuje. Před pohybem se ověřuje rezerva pro
kalibrovaný pohyb i zbývající lifecycle. Tím se opravuje drift, nikoli parametry
legacy scény. Jeden tick má omezenou práci; pauza CPU není hardwarový watchdog.
Po synchronním zápisu journalu se znovu čte stejný monotónní clock. Zápis
neposouvá začátek ani deadline: prošlé cue se nedohánějí a opožděné dokončení
neobnoví dostupnost. I když už byl návrat uložen, zůstane nutná inspekce;
uložená deduplikační identita se zachová.

## Build a authoring

Z kořene repozitáře:

Host runner používá C++14 compiler (g++ nebo Windows Visual Studio Build Tools)
a Node. Pro zachovaný přísný WSS output verifier nejprve jednou spusť
`npm ci` v `contracts`, kde zůstává původní lockfile.

```text
python mechanika/final/generate_effects.py
python mechanika/final/generate_effects.py --check
python mechanika/final/test_effects.py
python firmware/tests/run_show_tests.py
python firmware/tests/compare_legacy_show.py
python scripts/check_dv02.py
node --test mechanika/final/test_show_timeline.cjs
```

Překlad má uzavřené schema, limit velikosti/hloubky a sémantické kontroly. Bez
eval, skriptů, URL, runtime DAG nebo stažení scén. Generuje `PresentationScore.h`,
`effects.plan.json` a `effects.manifest.json`; všechny vycházejí z jednoho IR.
Hash zdroje, compileru, payloadu a balíku jsou identity, nikoli oprávnění.
Firmware CMake i CI odmítnou zastaralé generované artefakty. Check režim nepíše.

Pojmenované main/short zůstávají současnými presentation variantami. Nové
akcenty jsou explicitní opt-in katalog bez automatických triggerů. LED-only
profil nepřidává právo k servo pohybu. `special-referral` vyžaduje upstream DV11;
neexistuje náhodný referral ani sedmý slot. SceneIntentBridge je lokální úzký
kontrakt se syntetickými integračními testy; upstream DV01 transport není zapojený.
`choice_accent` jen váže existující selection autoritu a nikdy nezaloží další reveal.
V aktuálním backendu existuje interní enum `SceneIntent` a nullable pole v
`CharacterDirective`/lore. `CharacterDirector` toto pole při vytváření directive
neplní a stávající firmware v1 ho nepřenáší. Jde tedy o existující DV01 kontrakt
bez živé device capability, nikoli o neexistující DV01 personu. Audit této hranice
byl zdrojový: Roslyn potvrdil přesný checkout bez solution; nevytvářela se nová
solution, nespouštěl restore/build ani se netvrdila úplnost compiler references.

## Časy, audio a Stop

| Capability | Skutečný stav |
|---|---|
| Device clock | Lokální monotonic ms, konkrétní boot; overflow/rollback se odmítá. |
| Deadline | Stávající limit 15 s od přijetí, včetně přípravy, handoff a cleanup. |
| Servo completion | Časování podle provisionované kalibrace slotu; žádné měření polohy. |
| Jas / vibrace | Stávající driver cap 64/255 a pulz nejvýše 150 ms; mechanická/elektrická akceptace zůstává G. |
| Lokální tón | TryCue dokládá enqueue/refusal. Worker používá stejné I2S, žádný mixer. |
| Stop tónu | Revokace budoucích bloků; již přijatý blok do 20 ms a DMA mohou doznít. |
| Řeč | Existující aplikační playback/drain; není word marker API pro scény. |
| Audio synchronizace | Phase-only / enqueue-proxy; žádný důkaz akustického okamžiku. |
| Dance čas | Absolutní pozice streamu a racionální BPM výpočet, žádné dohrávání vynechaných beatů. |
| Akustické měření / DMA jitter / ESP heap a stack | Pro novou sestavu neověřeno; vyžaduje fyzickou bránu G. |

Response cancel, session revokace a show Stop mají oddělené scope. Zrušení
dekorace nepřeruší přijatou fyzickou presentation. Globální Stop má přednost
před startem, nehraje outro a neprovádí kompenzační lower. Starý callback nesmí
uvolnit novějšího vlastníka. Při chybě nelze obnovit provoz jen uplynutím timeru.

## Trace a replay

Aktuální rozšíření stejných ownerů a observer kontraktu pro nativní Linux runtime
a odchozí ESP ingest popisuje [Digital Twin](digital-twin.md). Lokální trace endpoint
zůstává read-only; sám o sobě neposkytuje device-to-cloud dostupnost.

Device poskytuje nový samostatný `GET /v1/show-trace` přes existující TLS a bearer
autentizaci. Přísný `/v1/control` WSS v1 nemění payload ani capability pole.
Endpoint nevydává povely, nevyžaduje ruční lease, nic nenahrává a neposílá AI.
Starší firmware endpoint nemá; to znamená chybějící capability.

Trace neobsahuje hostův text, audio, fotografii ani credentialy. Identifikuje boot,
operaci, scene/bundle, kalibraci a generaci. Časy/revize v JSON používají decimal
strings; viewer nesmí ztratit přesnost konverzí do JavaScript Number. Ring má
64 záznamů, přepis nejstaršího zvýší drop counter a zachová sequence mezeru.
RGB je požadovaný vstup driveru; `level` uvádí účinný intenzitní vstup. Stará
stopa bez `level` má intenzitu unknown. Viewer nedopočítává údaj o změřených LED.
`observerSkippedSnapshots` znamená nepublikovanou kopii, nikoli úspěch/fail show.
`observerStale` označí snapshot starší 2 s nebo neslučitelný clock.

Pro zachování importovatelných souborů na Windows použij
`python firmware/tests/run_show_tests.py --only show_trace_replay --fixtures "$env:TEMP/dv02-replay"`.
Na jiném hostu předej `--fixtures` místní dočasný adresář. Stopy jsou z téhož C++ owneru. Ve
Workshop vieweru panel DV02 zobrazí plán, importovanou stopu a baseline/candidate
diff. Import je omezený a neprovádí HTML, skripty ani akční pole. Seek a rychlost
mění jen zobrazení. Chybějící start/end nejsou dopočítaným fyzickým důkazem;
ACK, commanded a timed-complete jsou zobrazeny odděleně od měření.

Skutečný viewer se regeneruje přes `preview.py --viewer-only` v existujícím CAD
prostředí podle [F2 README](../mechanika/final/README.md). Změna vieweru samotná
neprohlašuje znovu přijatý výrobní ZIP ani fyzické CAD clearance.

## Rollout a rollback

Compiled scény jsou součástí schváleného firmware; žádná síťová cesta neumí
nahrát libovolný plán. Běžná show drží svůj snapshot až do terminal outcome.
Kalibrace a pin profil se mění v klidovém servisním postupu. Rollback za běhu
nepřepíná player; nejprve skončit bezpečným stávajícím postupem, po Stop inspekce.

Journal v2 čte v1 a uchovává omezené durable tombstones operací. Při zaplnění
odmítá nové fyzické operace po 32 uložených ID; nevymaže starou ochranu kvůli nové show.
Rotace/archivace těchto identit vyžaduje explicitní bezpečný servisní postup,
který tento slice automaticky nezavádí. Tento limit je provozní brána při přípravě akce. Rollback
na starý firmware, který v2 nezná, musí zůstat fail-closed. Nesmí mazat NVS,
přeznačit nejasný výsledek ani vydat nový operation ID jako slepý retry.
Flash, Release, deployment, signing a placené modelové testy tento workflow
nespouští. Event-ready vyžaduje konkrétní fyzickou akceptaci G.

Repo skills jsou v `.agents/skills` podle [oficiálního mechanismu Codex](https://learn.chatgpt.com/docs/customization/overview#skills).
[Authoring](../.agents/skills/dildovander-show-authoring/SKILL.md) a
[debug/replay](../.agents/skills/dildovander-show-debug/SKILL.md) nezdvojují
persona eval ani UI skill. Syntax, odkazy a offline příkazy se ověřují; skutečné
discovery/reload nových skills v nové relaci se nesmí tvrdit bez pozorování.
