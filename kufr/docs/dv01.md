# DV01 · implementace a hranice ověření

Autorita požadavků je [specifikace 2.1 FINAL](dv01-specification.md), zejména
§3 bible, §7 signály, §8 finále/journal a §17 scénáře. Tento dokument popisuje
implementaci; samotná specifikace netvrdí, že proběhl Live nebo fyzický test.
[Work item](../../docs/project/work-items/DV01.json) a jeho receipts vedou výsledky.

## A–E a zdroje

| Část | Implementace | Důkaz / otevřená brána |
| --- | --- | --- |
| A baseline | [hashy](../ai-eval/dv01-baseline.json), beze změny původních person a katalogu | Kontrola bytů; žádná dostupná párová placená baseline |
| B director | `backend/Features/Character`, opt-in `GptLiveOptions` a stejný session owner | `CharacterDirectorTests`, fake Live průchody v `AutonomousLiveTests` |
| C závody | podkladové revize, oddělená response generation, zrušení lokálního audia/checkpointu, stávající device/NVS owner | Offline/fake; příslušnost unsegmented Live vzorků má limit níže |
| D zážitek | adult/chaos, max. 3 kotvy, 3 druhy finále, 6 katalogově svázaných lore, anonymní ID | Autorské fixtures; ostrý skutečný Live přednes/poslech čeká na C/D eval |
| E provoz | existující admin modes/Debug, diagnostika, offline replay, dva projektové skills | Build, testy a strukturální dry-run; nové skills se načtou v nové Codex session |

Director nemá I/O ani další modelové volání. Obyčejné repliky zůstávají Live,
výběr zůstává `WandDecisionService`. Tempo, zapojení, tón a audio jsou nezávislé.
Backend scoring a katalog se nepřepisují; DV01 do rozhodovacího vstupu nepřidává
roast, vizuální domněnku ani osobní příběh z jiné session. Pro DV01 je stávající
historická osobní textová paměť odpojená od roast promptu. [Show Pack](show-pack.md)
nově připojuje maximálně tři anonymní večerní motivy z doložených událostí;
cizí transcripty se mezi návštěvami nesdílejí. Vlastní návratová paměť vyžaduje
ověřenou vazbu a původní oprávnění. Archiv identity a kroniky je `manual_only`.

Čisté expresní povely jsou mimo evidenci; bez podkladu se výběrový model nevolá.
Expresní tempo nad platnou evidencí nepřebírá staré `NeedsInformation` z cache.

Host má obvykle dvě obsahové otázky, express žádné další. Jednoslovná odpověď
omezuje zpovídání, nemění adult na gentle. Třetí požadavek opravit nesrozumitelnost
ukončí neověřenou cestu a vyžaduje existující textovou/operátorskou větev. Po 90 s
se preferuje dokončení v klidném vstupu; endpoint má konečný 180s lifetime.
Jeden návrat k otázce po pěti sekundách vyžaduje skutečný čerstvý vstupní PCM,
čekání na hosta a nepřítomnost rozhodovací práce. Ticho není osobnostní signál.

## Signály, kotvy a fotografie

Přijatá řeč má source ID/revision, direktiva vlastní revizi a session generation.
Běžné české explicitní kontroly jsou konzervativní pravidla v existující projekci,
nikoli sémantický klasifikátor ani objektivní pravda. Citované „Stop“ nebo nápis
na tričku nepřebírají oprávnění. Oprava/atribuce zneplatní závislé textové kotvy
a před issued také staré rozhodovací podklady. Obyčejný comeback nesnižuje tón.
Samotný tón nemění scoring ani nevyžaduje další rozhodovací volání.

Kotva je krátké citované tvrzení/preference/fikce nebo explicitně oprávněné
pozorování; nejvýše tři dohromady. Barge-in ruší response, zachová session a kotvy.
Stažení tématu ruší dotčený podklad, fotografie ruší obraz a blokuje pozdní výsledky,
ukončení session vyčistí vše osobní. Znovupovolení neoživuje starý snímek.
Provenience dokládá zdroj, nikoli správné pochopení subjektu. U více mluvčích
není dostupná ověřená diarizace; při nejasnosti nepoužít osobní anchor, Live gate
zůstává otevřený. Ochrana UI Stop nepoužívá modelové rozhodnutí.

**Vizuální produkční větev je `permission_pending`.** Existuje jen souhlas s
analýzou kostýmu a stručný `CostumeContext`; chybí explicitní účel appearance roast,
observation ID/revision, jednoznačný zamýšlený subjekt a revokační workflow tohoto
účelu. DV01 proto tento kontext do herce ani selection nevkládá. Čistý kontrakt
permission/vision a late-result regrese jsou připravené a synteticky testované,
bez nového fotoaparátu, biometrie či portrait produktu. Oprávněný účes/kostým a
hostovo „jsem chudej“ mohou být komediální materiál, nikoli zdravotní či příjmový profil.

## Finále a audio capability

Výchozí profil DV01 je **Blocked**: rozhovor/fake volba fungují, ale
`CompleteAutonomousLive` nevydá fyzický `SelectionProposal`. **Named** je v config
i správě odmítnut s konkrétním důvodem; nezmění se automaticky na Limited.
Připravený **Limited** hostitel vybírá výslovně pro další session: řeč neuvádí
katalogové jméno ani slot, strukturovaný validovaný návrh se předává dosavadní cestou.
Jde o ztrátu slovní identifikace, nikoli přijaté named finále. Event readiness není doložena.

Live WebSocket nemá response ID, output-audio-done ani přesné přiřazení vzorků k
transkriptu. Stávající kontrola názvu je po playbacku. Pro DV01 není k dispozici
řízený přednes celého finále se stejným hlasem; nový TTS/voice/model nevzniká.
Viz oficiální [transkripty Live](https://developers.openai.com/api/docs/guides/live-conversations#transcript-deltas)
a [kontrola před playbackem](https://developers.openai.com/api/docs/guides/voice-server-controls?api=live#check-speech-before-playback).

`audio_cancel` má monotonickou lokální response generation. Swift zastaví pouze
player, zneplatní staré playback callbacks/checkpointy a zachová capture/session.
ESP uzavře output, vypíše tichý DMA tail a zachová input. Stop zůstává sticky.
Po omezení se provider PCM zadržuje: korelovaný nový directive ACK, klidová mezera
a následný nový transcript interval tvoří **heuristický fence**, nikoli důkaz
příslušnosti všech vzorků. Nové audio před titulkem se bounded bufferuje (96 kB,
nejvýše osm sekund), až potom se pustí. Chybějící transcript selže zavřeně.
Opožděný starý vzorek po tomto fence nelze protokolem odlišit od nového: tato mezera
vyžaduje Live a akustickou akceptaci. Žádný fake test ji nemění na tvrdou záruku.
U B-effects se SD hardwarově nemutuje; již přijatý DMA blok může krátce doznít.

Kontrola názvů celého aktuálního terminálního přednesu blokuje publikaci návrhu
při známém katalogovém názvu/slotu nebo vybraných nepravdivých pohybových tvrzeních.
Čísla slotů kontroluje i ve slovní české podobě, se skloňováním a interpunkcí.
Je post-hoc a syntaktická: nevrátí už slyšenou větu a nedokazuje absenci nové
smyšlené vlastnosti. Taková chyba je kritický Live nález, nikoli jen horší humor.

## Issued a restart

Backend SQLite je journal provider/idempotency/spotřeby, nikoli distribuovaný
physical commit. Pending/running se po restartu mění na unknown a provider se
automaticky nereplayuje. ESP `DeviceControlRuntime` serializuje acceptance:
aktuální boot/generation/revision, safety, kalibrace, připravenost a rezervace.
`PhysicalPresentation.Raise` nejprve získá `BeginAutonomousPresentation`; ten
uloží NVS `journal.Begin(proposalId, compartment)` **před prvním efektem/pohybem**.

PendingProposal před acceptance je pouze RAM. Ztráta před NVS záznamem nevytváří
automatický retry. Po NVS Begin přetrvá pending slot/ID/ready mask přes reboot,
blokuje další reveal a vyžaduje místní inspection. NVS neobsahuje osobní kotvy.
Nemá úplný archiv boot/evidence revision ani neúčinkový vzdálený reconciliation
endpoint: nelze tvrdit exactly-once či globální atomickou transakci. Neznámý stav
se řeší stávající místní obnovou, nikdy novým automatickým ID. Fyzická větev DV01
zůstává výchozí blokovaná, dokud příslušná sestava a korelace nejsou akceptované.

ACK znamená přijetí, návrat je `completed_by_timing`; senzory polohy neexistují.
Žádný návrh nezakládá pokyn vzít rekvizitu. Oprava po issued ruší slovní podklad,
nikoli fyzický výsledek nebo další reveal. Po publikaci backend přestane přijímat
nové tahy; fyzický owner a existující Stop rozhodují o probíhajícím pohybu.
Cleanup dialogu nemaže unresolved NVS operation; nový host ji nemůže obejít.

## Zapnutí, vypnutí a pestrost

Použijte existující Debug → správa serveru se zvláštním admin credentialem.
Vyberte `ollivander-trunk`, backend actor musí být `AutonomousActor`. DV01 má
checkbox, hostitelský Reserved/Dry/Adult/Chaos a Blocked/Limited. Adult je výchozí
opt-in preset pro dospělou roast akci; samotné zapnutí nic nemění na pravidlech služeb.
Konfigurace prostředí pro start procesu:

```text
Backend__GptLive__ActorMode=AutonomousActor
Backend__GptLive__Character__Enabled=true
Backend__GptLive__Character__HostTone=Adult
Backend__GptLive__Character__FinaleProfile=Blocked
```

Runtime admin změna má CAS revision a lifetime until_restart; každý create zamrazí
policy/persona/lore/catalog/profile. Checkbox off platí pro nové session, žádný
hot-reload právě mluvící persony. Zapnuté DV01 odmítne přepnutí na jinou personalitu;
nejprve DV01 vypněte. `Mírněji`, `bez nadávek`, `už mě neurážej`,
`fotku už nepoužívej` mají odpovídající omezený scope. `Nechci pokračovat` ukončí
backend session bez trestajícího outra; obsluha používá existující voice Stop/abort
a fyzický safety Stop pro okamžité bezpečné ukončení. Reset anonymní pestrosti
neřeší ani neruší nejistou fyzickou operaci.

Pestrost je jen bounded process-local whitelist ID: posledních šest opening IDs v historii,
dvanáct mechanism IDs a nasycené počty šesti lore. ID se aktualizuje při prvním
skutečně odeslaném audio chunku dané response jako doložený proxy, ne při pouhém
plánování či duplicitním checkpointu. Neprokazuje, že model dodržel mechanismus.
Event scope používá existující evening ID, bez něj device scope procesu; max. 32.
Restart/reset zahodí pestrost, nikoli physical journal. Žádné citace, fotky,
finanční příběhy ani jména jiných hostů. Show Pack rozšiřuje tento historický
rozsah o anonymní persistentní lore, náladu, repertoár a výslovně zapnutý místní
ambient; používá současná SQLite úložiště a audio/fyzické vlastníky. Idle může
spustit povolené světlo nebo připravenou hlášku, pokud nebrání Stop, obnova,
aktivní návštěva, souboj nebo chybějící audio. Bez banky se řeč nepředstírá.

## Autorské páry pro poslech

Toto jsou syntetické reference pro testy, **ne výstup skutečného modelu**.

| Podklad | Adult | Chaos |
| --- | --- | --- |
| „Jsem nejlepší kouzelník.“ | Sebehodnocení sis dělal sám. To je kurva úsporný. | Ego sis přinesl ve velkoobchodním balení. Důkazy zase hovno; reklamace beru na lopatě. |
| „Ztrácím klíče denně.“ | Ty už neztrácíš klíče, ty provozuješ zasraný předplatný pátrání. | Tvoje klíče mají vlastní program ochrany svědků. Kurva, i kov má pud sebezáchovy. |
| „Nevím, vyber.“ | Konečně někdo delegoval práci na jedinej funkční mozek v místnosti. | O sobě jsi mi řekl hovno. Dobře, charakter dneska dodá hůlka; účet za ego necháme prázdnej. |
| „Jsem chudej.“ | Ty nemáš prachy, já trpělivost; aspoň nemusíme předstírat bohatství. | Magii na splátky nevedu. Tvoje peněženka má kurva větší talent na zmizení než ty. |

Oprava: „To s klíčema byl můj brácha, ne já.“ → „Tak to vracím do správný složky.
Rodinnej chaos mi nezaváděj do evidence.“ Kotva i závislé nepublikované zdůvodnění
se zneplatní; po možném issued není druhý reveal. „Už mě neurážej“ → „Dobře.
Zůstanu u hůlek.“ Žádná následná osobní pointa.

## Replay, mapování a readiness

Pro čistý checkout nejprve obnovte závislosti backendu podle jeho Linux lockfile
(také na Windows funguje restore bez přidání Windows apphost RID): v `kufr/`
spusťte `dotnet restore backend-tests/BackendTests.csproj -r linux-x64
-p:UseAppHost=false --locked-mode`. Replay potom používá `--no-restore`, aby
nezměnil existující produkční lockfile. Defaultní Windows locked restore bez RID
vrací NU1004; není to DV01 závislost ani důvod přegenerovat lockfile.

[R01–R34/T01–T80](../ai-eval/dv01-scenarios.json) zachovávají celé scénáře;
[coverage](../ai-eval/dv01-coverage.json) odkazuje na konkrétní testy a chybějící
capabilities. Čísla nejsou počet běhů ani důkaz celých scénářů. Offline `--character`
spouští guards/fake hranice a feature-off suite; celé backend testy zachovávají
staré regrese. C skutečné modelové chování a D poslech/mechanika jsou oddělené.

```text
python kufr/ai-eval/evaluate_party.py --dv01-check --output kufr/ai-eval/results/dv01-check.json
python kufr/ai-eval/evaluate_party.py --dv01-replay --output kufr/ai-eval/results/dv01-offline.json
python -m unittest discover -s kufr/ai-eval -p test_*.py
```

`--dv01-check` pouze parsuje metadata/reference a neprohlašuje offline behavior za
ověřené. `--dv01-replay` nemá provider ani hardware přístup a měří jen director
overhead na lokálním CPU. Root skills [design](../../.agents/skills/dildovander-character-design/SKILL.md)
a [eval](../../.agents/skills/dildovander-character-eval/SKILL.md) používají podporované
projektové `.agents/skills`; nová session načte nový katalog. Aktuální session
nemá discovery reload API, proto nový skutečný modelový routing není tvrzen.

Readiness musí uvádět zvlášť offline_verified, live_behavior_verified (adult/chaos,
text/vision), visual permission/support, named/limited/blocked, audio hardware,
physical reveal a event_ready konkrétní konfigurace. Live/placený test, macOS/iPhone
a skutečné pohyby nebyly tímto dokumentem autorizované ani nahrazené fake výsledkem.
